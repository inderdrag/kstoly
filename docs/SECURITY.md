# Безопасность

В приложении нет пользовательского входа. Серверные ключи AnyModel и Cloudflare не входят в APK, HTML и JavaScript. Не публикуйте .env, базу var, keystore, секреты или логи с персональными данными.

POST проверяет Origin, формат, согласие и размеры входа. Это ограничение браузера, не аутентификация: любой клиент способен сформировать Origin. API сознательно открытый.

По умолчанию: 20 подборов/сутки, 30 обращений к модели/сутки, один подбор одновременно, отдельная квота фото 5/сутки; краткий лимит 3 POST в минуту на адрес непосредственного соединения. За прокси несколько пользователей могут разделять адрес. X-Forwarded-For не используется как доверенный идентификатор. В БД краткого лимита хранится хеш адреса с временным окном, не сам адрес.

SQLite-квоты рассчитаны на один экземпляр и устойчивый DATA_DIR. На временном диске бесплатного хостинга после потери файлов лимиты сбросятся. Для публичного доступа обязательно установить жёсткий бюджет у провайдера и устойчивое хранение квот. Распределённые запросы и намеренная блокировка общего лимита не исключены. Безусловной защиты от расходов здесь нет.

Генерация требует явного подтверждения, проверенного бесплатного маршрута и идемпотентного requestId. Неопределённые сбои не должны незаметно запускать новую платную попытку. Результаты изображений живут на сервере ограниченное время. Произвольные URL из модели не загружаются.

Ошибки upstream нормализуются, журнал содержит ID запроса, этап и код, но не ключи, запросы с фото или сырой ответ провайдера. Старые /api/login и /api/logout оставлены как no-op для совместимости старых клиентов: они не проверяют реквизиты и не выдают сессию.

## Текстовый чат
`ANYMODEL_CHAT_MODEL=ds/deepseek-v4-flash`, отдельный `DAILY_CHAT_LIMIT=100` на сервер в сутки (UTC), максимум два одновременных запроса. Один ответ ограничен 1400 выходными токенами и 55 секундами ожидания. Вопрос — до 1200 символов, ограниченная история — только роли user/assistant. Размер POST ограничен 140000 байт. Краткий лимит адреса общий с подбором; отдельный дневной лимит не гарантирует долларовый бюджет.

Сервер валидирует рецепт и формирует системные инструкции сам; клиент не задаёт системную роль. Контекст считается данными. Советы не исполняются и не изменяют рецепт; ответы отображаются обычным текстом. Это не гарантия правильности советов модели.

UUID requestId и отпечаток содержимого предотвращают повтор того же задания. GET статуса не вызывает модель. После неизвестного исхода новая попытка требует явного действия; провайдер всё равно мог списать предыдущую. На старте сервера незавершённые задания помечаются неуспешными, без автоматической повторной отправки. Готовый ответ доступен 24 часа; удаление просроченных строк — при следующем POST. ID восстановления является случайным секретом доступа к ответу: API не имеет пользовательской аутентификации. Не публикуйте эти ID, локальные pending-задания или SQLite.

## Асинхронный подбор (1.1.1)
POST `/api/selection-jobs`: согласие, регион, валюта, 1–4 JPEG, пожелания и необязательный чек проверяются до старта. Случайный requestId 16–80 символов и SHA256 полного входа обеспечивают идемпотентность. GET `/api/selection-jobs/:id` — только состояние/прежний результат, без upstream и новых квот. Дневные лимиты общие с совместимым `/api/analyze`, одновременно допускается один подбор. Ограничение частоты POST сохраняется.

Бюджет времени всех попыток одного подбора — `SELECTION_TIMEOUT_SECONDS` (по умолчанию 300, диапазон 60–600), включая прежнюю единственную попытку исправления невалидного JSON. Сетевой сбой не запускает исправление/новую платную попытку. Модель может потребовать оплату даже при превышении времени. Нет обещания неограниченного ожидания.

Готовые результаты кешируются до 24 часов; просроченные записи удаляются при следующем POST. Перезапуск на том же диске сохраняет готовые ответы, но незавершённые задания становятся failed без повторной отправки. На временном диске кеш и квоты могут потеряться. Держите один экземпляр сервиса и настройте устойчивый диск и бюджет у провайдера. Не публикуйте коды восстановления.

## Явная отправка в 1.1.2
Клиенты передают `consent: true` только в запросе, запущенном нажатием «Подобрать блюда» или отправки вопроса. Отдельные обязательные галочки и повторный диалог обычного подбора убраны; пояснение о передаче данных остаётся рядом с действием. Серверная проверка флага сохранена, но не считается аутентификацией. Открытие шторки, выбор подсказки и ввод текста не вызывают платную модель. Неопределённый результат не повторяется автоматически.

## Двухэтапный подбор 1.2.0
`/api/selection-jobs` принимает mode recognize с 1–4 фото или mode plan с 1–80 названиями. План отклоняет повторные поля фото. Названия ограничены по размеру и формату, оборудование по allowlist; весь контекст пользователя — данные, не инструкции. Режим onlyOwn отклоняет рецепт с missing; базовые продукты строго ограничены. Привязки present проверяются по диапазону индексов подтверждённого списка. Это не независимая гарантия правильности распознавания или безопасности еды. Явная несовместимая техника отклоняется. Сохраняются квоты этапов/upstream, одна активная работа, идемпотентность, TTL и отсутствие автоматического повтора прерванного запроса. Обезличенные строки чека проверяются по единицам, валюте и источнику. Нового секретного ключа не требуется.
