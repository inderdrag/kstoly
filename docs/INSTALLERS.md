# EXE и APK — 0.7.0, первая тестовая версия

## Запуск на GitHub

Открой **Actions → Build installers — К столу → Run workflow**. Branch `main`, target `both`. `android_release` оставь выключенным для первой проверки. `publish_draft` создаёт черновик релиза, без публичной публикации.

Сборки запускаются ТОЛЬКО вручную. Они расходуют включённую квоту GitHub Actions, в приватном репозитории квота не бесконечна; Windows имеет свой тариф. Если GitHub просит оплату или показывает превышение лимита, не подтверждай автоматически.

После зелёного завершения jobs скачай ZIP **Windows-x64-installer** и **Android-APK** в разделе Artifacts внизу запуска. Распакуй ZIP. Если выбрано создание draft, файлы будут и в **Releases → Draft** вместе с SHA256SUMS.txt. Они не появляются до успешной сборки. Артефакты хранятся 14 дней; файлы, загруженные в Release, имеют отдельный срок хранения (не удаляются вместе с Actions artifacts).

## Что внутри

Windows: Electron/NSIS, использует текущий HTTPS-сайт Render. Node, preload, доступ к файлам, чужие домены, микрофон и геолокация веб-странице не предоставляются. Сессия и история хранятся отдельно в профиле приложения. Это Windows x64, не ARM/macOS.

Android: Java + системные Android-компоненты, **без WebView**. Android 8+, камера/системный выбор фото, необязательный чек, сжатие/ориентация JPEG, вход, подбор, выбор блюда, порции/оценка стоимости, пошаговый рецепт, сохранение до 50 рецептов, обмен текстом, генерация с просмотром и подтверждением, восстановление задания. Это отдельный нативный клиент, не перенос веб-страницы один к одному. Светлая тема; поиска и сохранения отметок шагов пока нет.

Сервер не меняется. Токены AnyModel/Cloudflare и APP_PASSWORD в установщики не попадают. Публичный URL сервера не является секретом. Android не сохраняет пароль, сессия в памяти — после нового запуска понадобится вход. Фотографии передаются только после согласия, в историю исходные фото/чек не записываются. Рецепты и принятые изображения хранятся в закрытом хранилище приложения. Backup отключён.

История веб-версии/Windows/Android не синхронизируется. Удаление Android-приложения или очистка данных удаляет его историю; полноценного экспорта архива пока нет. Нельзя хранить в тестовой сборке единственную копию важных данных. Для анализа и генерации нужны интернет и работающий Render; установщик не заменяет сервер. Платные тарифы и бесплатные квоты по-прежнему регулируются на сервере.

## Подпись Android

По умолчанию получается **PREVIEW** APK с отдельным package ID `ru.kstolu.app.preview` и debug-подписью. Ключ кешируется в Actions только для удобства тестирования. Кеш может быть удалён: это НЕ гарантия стабильной подписи и НЕ production-подпись. Preview и production (`ru.kstolu.app`) устанавливаются отдельно, история автоматически не переносится.

Для нормальных обновлений нужен один постоянный приватный JKS-ключ с резервной копией вне Git. На доверенном компьютере с JDK:

```bash
keytool -genkeypair -v -keystore k-stolu-release.jks -alias kstolu -keyalg RSA -keysize 3072 -validity 10000
```

Пароль вводится по запросу `keytool`, не в аргументах и не в чате. JKS и его base64 — секреты. Не публикуй их, не выводи в общий терминал и не добавляй в репозиторий.

В **GitHub → Settings → Secrets and variables → Actions → New repository secret** понадобятся:

- `ANDROID_KEYSTORE_BASE64`: JKS в base64 без переносов;
- `ANDROID_KEYSTORE_PASSWORD`;
- `ANDROID_KEY_ALIAS`, например `kstolu`;
- `ANDROID_KEY_PASSWORD`.

Для подготовки base64 используйте локальный доверенный компьютер, не выводите содержимое в публичный журнал. Пароли и JKS храните в менеджере секретов и резервной копии. Затем запускайте workflow с `android_release=true`: отсутствие любого секрета остановит сборку, скрытого debug-fallback нет. Ключ не попадает в artifacts и удаляется с временного runner после сборки. Каждое обновление должно увеличивать `versionCode` в android/app/build.gradle, не менять applicationId и использовать тот же ключ. Потеря ключа для sideload APK лишает возможности обычного обновления.

## Установка и проверки

APK — личная установка, не Google Play. Android попросит разрешить установку из источника: делайте это только для файла из собственного репозитория. Не отключайте Play Protect. Windows EXE пока без Authenticode: SmartScreen/организация могут его ограничить. Не отключайте защиту системы; сертификат издателя и автообновления — отдельный этап и возможная стоимость.

Перед использованием проверить Android на устройстве: установка, вход/выход, камера и галерея, ориентация фото, чек, отказ от отправки, выбор разных блюд, стоимость/порции, сохранение/офлайн-история, генерация/отказ/принятие/продолжение, перезапуск, обновление той же подписью. Windows: установка без администратора, запуск, вход, камера/галерея, сохранение, повторный запуск, удаление. До этих проверок не называть приложения проверенными на устройствах.

## Локальная сборка разработчиком

Windows: Node 24, `cd desktop && npm ci && npm test && npm run dist:win` (Windows runner). Android: JDK 17, SDK platform 35/build-tools 35.0.0, Gradle 8.11.1; `cd android && gradle :app:lintDebug :app:assembleDebug`. Для production передать переменные подписи из безопасного окружения. Приватные ключи и APK/EXE не коммитить.


## Проверено при подготовке

APK скомпилирован локально Android Gradle Plugin 8.9.2 / Gradle 8.11.1 / SDK 35, Android Lint выполнен. Нативные экранные тесты Robolectric проверяют навигацию, настройки, неизвестные цены, сохранение истории, отсутствие автоматической генерации и отказ от фото; снимки экранов просмотрены при размере 390×844. Это не тест камеры/установки на реальном телефоне. Политика Windows-origin и разрешений проверяется Node-тестами. Локальная кросс-сборка NSIS остановилась из-за отсутствия Wine; Windows-сборка должна подтвердиться на windows-latest в Actions. Не использовать частичный EXE из неудачной локальной сборки.
