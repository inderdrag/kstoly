# Подбор после подтверждения продуктов — Android 1.2.2

Воспроизведён сценарий: в настройках одновременно остаются подтверждённый список `reviewedInventory` и готовый результат распознавания `readySelection`. Раньше нажатие составления блюд возвращало этот список вместо POST с `mode:plan`. Теперь только уже завершённый результат распознавания потребляется перед явным запросом плана; готовые рецепты и незавершённые задания не выбрасываются.

Ещё один дефект обратной связи: этапы и ошибки находились только в начале длинного списка. Теперь кнопка немедленно меняет подпись/состояние, а сообщения дублируются под ней. Запоздалый прогресс после завершения задачи игнорируется. Ошибка не удаляет список, повторное явное нажатие создаёт новый ID без фото. При активном или неопределённом задании сохраняется GET-восстановление, не новая платная отправка.

## Проверки без внешней модели

`SelectionRetryUiTest`: загрузка и двойное нажатие; ошибка и повтор с другим ID; оставшийся готовый список распознавания; восстановление старой ошибки через GET; открытие готового рецепта без сети. Эти проверки не утверждают, что диагностировано точное состояние конкретного телефона пользователя, и не заменяют испытание на устройстве.

Для использования исправления нужно собрать APK 1.2.2 через Actions → Build Android — К столу → Run workflow на main и установить поверх старой с той же подписью. Не удалять приложение, не очищать данные и кеш ключа подписи. Сервер 1.2.1 совместим; менять ключ API не нужно.
