# Android 0.9.0: проверка и установка

## Обновление

1. Дождитесь деплоя main в Render. `/api/status` должен возвращать `build: "0.9.0"`.
2. GitHub → Actions → Build installers — К столу → Run workflow → main → target `android`.
3. Для обновления существующего PREVIEW оставьте `android_release` выключенным, `publish_draft` включённым. Ключ кеша `k-stolu-preview-signing-v1` не менялся. При утрате кеша подпись может смениться — не удаляйте приложение для обхода несовместимости.
4. После успеха скачайте из черновика Releases `K-Stolu-0.9.0-Android-PREVIEW.apk`, установите поверх прежней версии. Не берите APK, собранный с другим локальным debug-ключом.
5. Windows не менялся; сборка только Android достаточна.

## Границы и данные

- API принимает `images` из 1–4 сжатых JPEG, либо прежнее одиночное `image`; вместе их передавать нельзя. Отдельный `receipt` — один JPEG. Каждый до 1500 px и 2 МиБ, суммарное тело до 15 МиБ.
- `preferences`: `hearty`, `quick`, `no_salads`, `no_oven`. Только известные значения, без дублей. Пожелания входят в тот же запрос, не в отдельный платный анализ.
- До двух попыток модели на подбор, включая единственное исправление ответа. Никаких дополнительных обращений за подробностями отдельных рецептов. Максимум 10 блюд; подробность может увеличивать время и расход токенов текущего тарифа.
- `steps` до 20; `body` до 2600 символов. `timer_seconds`: целое 1–21600; `timer_hint`: до 240. Недостоверные таймеры отбрасываются без нового платного запроса. В старых шагах время можно задать вручную.
- `equipment`: необязательный список `hob`, `oven`, `microwave`, `kettle`, `none`. Для совместимости старых рецептов поле необязательно. «До 20 минут» учитывает подготовку и готовку.
- Папки и оценки — отдельные локальные данные, не переписывают текст и идентификатор старых рецептов. Ручные цены хранятся отдельно, по названию продукта, единице и валюте; не выдаются за цену чека или проверенную цену магазина и не отправляются генератору.
- Фотозадание сохраняется до отправки, запрос повторного создания с тем же requestId идемпотентен на сервере. На тайм-ауте клиент сохраняет задание. Готовый результат кешируется приватно до принятия/отказа; просмотр без сети не вызывает генератор.
- Сессия остаётся зашифрованной AndroidKeyStore. Пароли и API-ключи в APK не добавляются. История сайта/Windows автоматически не переносится.
- Таймер основан на elapsedRealtime; хранится один активный сеанс готовки. В фоне нет обещания звука/уведомления. После перезагрузки телефона — пауза, не ложное автоматическое завершение. При смене блюда требуется подтверждение замены таймера.

## Проверка на телефоне перед распространением

- Обновление поверх старого APK: сохранённые блюда и действующая сессия остаются.
- Камера + выбор нескольких из галереи; 4 фото максимум, удаление одного; отмена выбора не удаляет остальные. Поворот экрана/возврат из галереи, большие фото и фото с EXIF-поворотом.
- Все 4 пожелания; разнообразные горячие блюда и категории. Старые веб-запросы с одиночным фото работают.
- Поиск по двум словам, папка, своя папка, несколько папок одного блюда, пустой результат поиска; оценка после приготовления.
- Ручная цена в рублях за 1000 г и за штуку, дробная цена с запятой; изменение порций; неполная цена не выглядит полной или нулевой.
- Готовка: свайпы, кнопки, отключённые системные анимации; подробный длинный шаг прокручивается. Таймер не запускается при открытии. Пауза, продолжение, изменение, сброс, один переход после истечения; следующий таймер сам не запускается.
- Сворачивание/возврат, поворот, завершение процесса системой, перезагрузка телефона. Безопасность готового мяса/рыбы/птицы проверяется отдельно, не по таймеру.
- Фото: создание после согласия, тайм-аут → получение прежнего результата, закрытие готового предпросмотра → повторный просмотр, принятие/отказ. Проверять платные сценарии только с согласия владельца; автоматические тесты используют заглушки.
- Экранная клавиатура, крупный шрифт, Android 15 edge-to-edge и навигационные жесты. Эмуляторные снимки не заменяют эти проверки.
