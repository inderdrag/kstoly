# К столу · 0.6 · фотографии блюд

## Поведение

Генерация по умолчанию выключена. В настройках нужно включить «Разрешить генерацию фото», затем открыть конкретный рецепт → «⋯» → «Создать фото блюда» и подтвердить отправку состава. Создание по одному изображению, без автоматической регенерации. Передаются название, количества ингредиентов и способ приготовления, не исходные фотографии и не чек. Генератор может представить блюдо иначе, чем оно получится; подпись всегда «Изображение ИИ».

По умолчанию ANYMODEL_IMAGE_MODEL=am/flux.2-klein-4b. Перед созданием сервер проверяет /v1/models/info и принимает только модель kind:image с billing.unit:image и обеими коэффициентами 0. Неподтверждённый или платный тариф блокируется. Кеш проверки — 60 секунд. Это проверка опубликованного тарифа, а не гарантия неизменности расчётов поставщика. Смена маршрута на платный не поддерживается этим выпуском. Ключ остаётся в переменной окружения сервера, менять существующий ключ для этой функции не требуется. Реальная доступность маршрута текущему аккаунту проверяется первым пользовательским запросом.

До 5 попыток создания в день UTC; одновременно одна активная генерация. Неудачная попытка тоже входит в лимит. Получение результата не создаёт новую генерацию. Счётчики SQLite на бесплатном Render не переживают потерю временного диска; это не лимит расходов у поставщика. Необходимо также ограничивать ключ у AnyModel.

## Хранение и повторное открытие

Изображение сжимается в JPEG до 960px и сохраняется Blob в IndexedDB. Максимум 50 фото, до 2МБ каждое. Рецепт сохраняется в существующей локальной истории; количество порций не влияет на привязку фото. Сохранённые изображения доступны и при выключенной генерации. В браузере и будущем APK отдельные хранилища; автоматического переноса или синхронизации пока нет.

История рецептов и фото управляются отдельно. Удаление фото не удаляет рецепт; очистка истории не очищает отдельную библиотеку фото ИИ. Полностью удалить изображения можно в настройках. Очистка данных приложения/браузера удалит локальные данные. Это не резервная копия.

## Асинхронные задания

API шлюза документирован на https://anymodel.org/api-docs.md. Создание запрашивается с background:true, n:1, size:1024x1024, response_format:b64_json. Сервер хранит только идентификатор задания и счётчики, не изображение в базе. При синхронном ответе хранит результат в памяти максимум 10 минут; при перезапуске такой результат может потеряться. Получение результата асинхронного задания доступно у шлюза до 24 часов.

Клиент сохраняет идентификатор запроса до отправки. Повторное нажатие «Продолжить получение фото» получает прежнее задание; POST с тем же идентификатором идемпотентен на сервере. При ошибке или истечении времени новое изображение не создаётся само. Забыть задание можно отдельно в настройках; это не отменяет его у поставщика. В фоне мобильный браузер может приостановить ожидание — после возвращения продолжите получение.

API всегда требует owner cookie. POST сохраняет проверку точного Origin. Модель, адрес шлюза и промпт задаёт сервер. Произвольные ссылки и URL из ответа модели не загружаются. Принимаются ограниченные PNG/JPEG; PNG не больше 4096px/16Мп, JPEG до 1500px/2МБ. Клиент дополнительно проверяет размер при декодировании и сжимает картинку. Ошибки шлюза не выводят сырые тела и секреты.

## Статус проверки

Модульные и HTTP-тесты используют поддельный fetch. Браузерные тесты подставляют тестовое изображение вместо реальной генерации. Тестовая картинка не является результатом FLUX. Запросы с настоящим ключом, списания и доступность модели не проверены агентом.

## Ручная проверка на телефоне

- [ ] После обновления видно название «К столу» и иконку с листом.
- [ ] Ранее сохранённые рецепты открываются, история не очищена.
- [ ] В настройках генерация изначально выключена.
- [ ] При включении видна проверка тарифа или понятная ошибка доступа.
- [ ] Если тариф не подтверждён бесплатным, создание заблокировано.
- [ ] В меню рецепта появляется «Создать фото блюда».
- [ ] Отмена подтверждения не создаёт задание.
- [ ] Одно подтверждение создаёт только одно задание.
- [ ] На время создания кнопка отключена, ошибки понятны.
- [ ] Готовое фото подписано «Изображение ИИ», рецепт добавлен в историю.
- [ ] После закрытия и повторного открытия фото доступно без нового запроса.
- [ ] Изменение количества порций не теряет фото.
- [ ] Выключение генерации не удаляет сохранённые фото.
- [ ] Удаление фото оставляет рецепт и возвращает пример из библиотеки/заглушку.
- [ ] Очистка фото в настройках не удаляет историю рецептов.
- [ ] Продолжение незавершённого задания не создаёт новый запрос.
- [ ] Тёмная тема, отсутствие интернета и возврат из фона не ломают историю.

Типичные ошибки: многократное нажатие при долгом ответе; очистка данных браузера вместо обновления страницы; ожидание синхронизации между телефоном и ПК; попытка вставить API-ключ в приложение. Ключ вводится только на сервере, скриншоты секретов не отправлять.
