# Олива — личный фото-помощник

Версия 0.4. Сервер Node.js 24 + PWA на обычных HTML/CSS/JavaScript, без сторонних runtime-зависимостей. Оформление по присланному макету «Олива».

## Честный статус

Код подготовлен и проверен локально. В настоящий AnyModel запросов ещё не было. Поддержка изображений и выбранного модельного маршрута должна быть проверена на реальном ключе. Проект не является публично запущенным сервисом. Наличие файлов в GitHub не означает, что сервер уже работает.

## Что реализовано

- Вход владельца по отдельному паролю, HttpOnly/SameSite cookie, защита POST по Origin.
- Камера/галерея; конвертация в JPEG до 1500px, максимум 2МБ после сжатия. Исходное фото до 20МБ.
- Необязательное фото чека, согласие на передачу фотографий посреднику и поставщику модели.
- Серверный запрос в `https://anymodel.org/v1/chat/completions`. Секрет только в окружении.
- Строгая серверная проверка структуры JSON; максимум одна повторная попытка при невалидном ответе. Текстовая инструкция JSON используется по умолчанию: поддержка `response_format` именно выбранным маршрутом ещё не подтверждена.
- Подбор 3–5 разных блюд из сочетаний видимых продуктов (1–2, если продуктов мало); экран выбора с временем, стоимостью и составом; переход к полному рецепту и обратно без нового запроса. Для каждого блюда 1–8 порций; оценка цен или распознанные цены чека; неизвестные цены не считаются нулевыми.
- Арифметика по граммам/миллилитрам/штукам выполняется кодом; диапазон цен и сумма на порцию.
- Пошаговая готовка, копирование и системное меню отправки.
- Локальная история до 50 рецептов с маленькими миниатюрами продуктов, поиск, удаление. Фото чека не сохраняется в историю.
- Светлая/тёмная/системная тема, ручной регион и валюта. Геолокации нет.
- Манифест и service worker: оболочка кешируется, API и фото не кешируются. История доступна офлайн после первого успешного посещения. Новый рецепт требует интернета.

## Ресурсы изображений

Иконки и тестовый JPEG хранятся в `scripts/assets.json` в base64. `scripts/prepare-assets.mjs` автоматически восстанавливает их при `npm test` и `npm start`, без сетевых запросов. Сгенерированные бинарные файлы исключены из Git.

## Локальный запуск для разработчика

Нужен Node.js 24. Python не нужен. Пока у пользователя ничего устанавливать не требуется: планируется размещение на сервере.

1. Скопировать `.env.example` в `.env`.
2. Локально заполнить `APP_PASSWORD` (16+ символов), `SESSION_SECRET` (32+), при необходимости `ANYMODEL_API_KEY`.
3. `npm test` — все тесты должны пройти, реальный ключ не используется.
4. `npm start` — сервер сообщит о запуске на порту 3000.
5. Открыть `http://localhost:3000`. Без ключа доступен только учебный пример.

Не открывать `public/index.html` двойным щелчком как рабочее приложение: серверные функции требуют HTTP/HTTPS.

## План размещения

`render.yaml` описывает один бесплатный Node-сервис с автоматически генерируемыми APP_PASSWORD и SESSION_SECRET и вводом API-ключа через секретные настройки хостинга. Оплата и создание сервиса без подтверждения пользователя не выполняются. `RENDER_EXTERNAL_URL` задаёт Origin; вне Render нужно явно указать `PUBLIC_ORIGIN=https://адрес-приложения`.

ВАЖНО: у бесплатного Render временная файловая система. SQLite-счётчики в `./var` сохраняются только пока сохраняется этот диск; при потере файлов/замене экземпляра они обнулятся. Поэтому эти лимиты не являются надёжным месячным денежным потолком. До добавления постоянного хранилища и проверки защиты — только личный тест с небольшим балансом и лимитом ключа у AnyModel. Постоянный диск/другую БД выбирать отдельно с явным согласием на стоимость. Не увеличивать число экземпляров.
